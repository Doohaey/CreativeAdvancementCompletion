# 冒险的设计理念和落地大纲

## 冒险设计理念

Adventure对部分Region或GeoScope配置野区语义。冒险机制在这些区域内生效。野区不能与已经作为社区主体范围使用的Region重叠。

冒险机制由区域产出和占领战争叠加构成。区域产出机制让不同野区以不同玩法闭环产出兑换货币、金钱和装备。占领战争机制让被配置为可占领的野区在规则化窗口内被个人、庄园或领域争夺，并以占领权影响后续周收益。

冒险玩法分为开放世界遭遇和固定场地小游戏。开放世界遭遇依赖随机事件、月相、玩家加载范围和区域危险等级。固定场地小游戏依赖预先设计的场地、SubSpace边界和明确的目标行为。

Adventure只解释野区玩法，不修改WorldGeo和Community的内部存储。空间、时间、事件、统计、国库和玩家账户都通过下层公开API取得。Adventure可以在自己的持久化中记录野区配置、事件进度、收益记录、占领权、战争窗口和防刷图层，但外键必须使用下层提供的稳定编号。

## 下层 API 需求

Adventure按设计落地需要以下下层API。

### WorldGeo API

1. 空间查询：按坐标解析Region、GeoScope和SubSpace；按mark查询野区候选；读取空间名称、维度、形状、面积、玩家列表和进入离开事件。
2. 空间设置：注册并读取`adventure:`命名空间权限和规则，例如战争窗口传送限制、野区活动启用、可占领开关。WorldGeo只存储布尔值，不解释冒险语义。
3. SubSpace：战争据点、交付点、固定场地小游戏边界和临时活动场地都使用SubSpace承载。
4. 时间服务：读取Minecraft tick、游戏日、天气、月相、现实自然周和时区周期。
5. 行为事件：读取或订阅伤害、击杀、死亡、容器交互、物品使用、方块变化、玩家进入离开空间。
6. 统计查询：按空间、玩家、行为类型和周期读取事件聚合，用于防刷、战争贡献和区域热度。
7. 临时效果：通过timed effect overlay给野区或据点施加短时效果。

### Community API

1. 查询玩家可代表的个人、庄园和领域主体。
2. 查询社区成员、身份、权限、可显示称号和组织状态。
3. 查询和写入国库，写入时记录来源、外部引用和本地化说明。
4. 查询社区发展度和政策快照。
5. 向社区成员广播冒险分红、战争窗口和结算状态。

### Economy API

1. `transact`按玩家UUID执行加款和扣款，玩家在线状态不参与交易判断。
2. `getBalance`按玩家UUID查询现有账户余额。
3. 保证金与结算返回交易编号、状态、交易前余额和交易后余额。
4. 来源命名空间与唯一外部引用防止奖励、保证金和退款重试时重复执行。
5. 流水API支持按账户与时间分页查询及指定条目详情。
6. Adventure来源流水由Adventure结算详情协调回退，Economy不执行单边回退。
7. Adventure不规定Economy内部钱包、命令或数据库组织方式。

## Adventure 菜单与消息承载

Adventure需要建立与Community相同层次的玩家交互结构。`entrypoint/screen`承载箱子菜单标题、槽位、按钮、lore、分页和返回链；`application/interaction/screen`承载权限、主体选择、扣款、结算查询、失败处理和跨模块API调用；`application/interaction/message`承载可点击消息、结算通知、事件提示和广播。domain只返回可展示的视图模型，不直接引用Minecraft菜单、ItemStack或聊天组件。

Adventure菜单入口包括冒险总览、野区列表、野区详情、收益历史、战争窗口和管理配置。箱子菜单用于完整操作闭环；可点击消息用于进入提示、事件预警、结算摘要、失败重试和战争广播。箱子菜单点击后需要阅读多行聊天说明时，先关闭菜单再发送消息。

Adventure展示信息按四层处理。玩家可见层展示区域名称、风险等级、模糊影响因素、可参与动作、成本、结算结果和待结算状态。组织管理者可见层增加分红比例、国库影响、战争保证金和组织收益。OP可见层增加配置、运行中事件、异常队列、失败重试和数据修复入口。系统私有参数包括随机种子、精确公式、掉落权重、防刷图层和事件抽点失败细节。


## 服务器玩家特点

会参与野区战斗的服务器玩家普遍已进入生存后期，并拥有顶配装备。玩家可能通过传送方法脱离战斗，也可能以灵活视角、小地图和其他信息工具进行侦查。视角博弈和信息遮蔽的设计可靠性较低，战斗机制的大头应建立在硬碰硬对抗、明确目标和可计分行为上。

野区需要通过通用空间设置向外部传送系统提供可查询状态。传送系统读取空间状态后，可以限制野区或战争窗口内的传送行为。Adventure本身负责解释野区规则，底层空间系统只提供可查询的空间状态和进入离开事件。

传送限制不应写成WorldGeo的“野区传送规则”。Adventure注册通用扩展规则键，例如`adventure:teleport_restricted`和`adventure:war_window_active`。传送系统只读取布尔状态和空间归属，是否因为野区、战争或临时活动导致限制，由Adventure设置这些键并在Adventure文档中解释。

## 野区定义与限制

野区需要表现危险氛围。玩家进入野区时，系统应以进入消息、音效、状态提示或地图标记提示风险。野区强度由危险等级、月相、区域地理标签和近期产出热度共同控制。危险等级参考月相的乘数方式影响数值；区域地理标签从WorldGeo API读取。

野区奖励分为五类：拒绝掉落、高档物品、趣味物品、数字金钱和基础兑换物品（四级兑换货币）。产出具有不确定性，直接产出以四级兑换货币为主。掉落受到稀有度、地理情况、防机械刷取图层和随机数共同调控。

野区配置由OP命令创建，由Adventure持久化，至少包含Region或GeoScope编号、危险等级、地理标签覆盖、是否可占领、战争窗口配置、产出表引用和进入提示模板。进入提示模板支持区域名称、危险等级、维度、可占领状态等配置内元素变量。Adventure创建野区时先通过WorldGeo查询确认目标空间不是Community主体Region，并确认同一空间没有被其他Adventure配置重复占用。

野区菜单落地为野区列表、野区详情、活动状态、收益历史和管理配置。野区列表显示空间名称、维度、危险等级、当前事件状态、可占领状态和模糊收益类型。野区详情显示进入提示、推荐准备、危险等级、最近结算摘要和可参与入口。管理配置页只向OP展示Region或GeoScope编号、产出表引用、事件额度、危险等级和运行状态。

野区消息包括进入提示、危险状态变化、事件预警和收益待处理。玩家消息展示方向、强度描述、撤离建议、收益结果和待结算状态；系统私有参数保留掉落权重、防刷热度数值、抽点随机种子和失败抽样明细。

## 参与主体与收益归属

冒险参与主体分为个人、庄园和领域。玩家直接取得收益，不存在收益归属选择。未加入社区的玩家以个人身份参与，收益全归本人。已加入社区的玩家，其冒险金钱收益必须按分红规则分配给所在社区：国库取得30%，参与成员按贡献分配70%。玩家同时处于一个庄园级别社区和一个领域级别社区时，两个社区各自收取30%，玩家自留40%。国库分红比例固定为30%，不可由管理者调整。

分红只针对Economy金钱。四级兑换货币、装备和物品作为实物原地生成，谁拾取归谁，不参与国库拆分。

战争窗口开启时，玩家选择本窗口的效忠对象。效忠对象可以是个人、庄园或领域。效忠对象每周只能切换一次；玩家同时加入一个庄园级别社区和一个领域级别社区时，默认效忠庄园。窗口持续期间，击杀、死亡、占点、保证金、即时收益和战功都记入同一效忠对象。

庄园和领域作为参与主体时，冒险系统生成收益记录。收益记录包含参与主体、参与成员、贡献明细、事件来源、空间位置、结算时间和分红状态。成员贡献只由两项构成：在事件或战争区域内每在场10分钟计1分，击杀敌对玩家一次计10分。

参与主体在Adventure内统一建模为`个人主体`、`庄园主体`和`领域主体`。个人主体使用玩家UUID；庄园和领域主体使用Community API返回的稳定组织编号。Adventure保存效忠对象选择，不在Community中写入冒险状态。分红结算时，Adventure先生成不可变收益记录，再调用Economy和Community API入账；任一入账失败时，该收益记录保持待结算状态，后续重试，不重新计算掉落随机数。

效忠对象选择菜单在战争窗口报名时使用。页面展示玩家本人、所在庄园和所在领域，显示组织名称、成员身份、可参与权限、入账主体和分红说明。不可代表的组织可以显示为只读说明或隐藏，权限阻断必须在handler层再次校验。选择完成后写入Adventure效忠记录，不回写Community业务状态。

## 开放世界遭遇事件

开放世界遭遇事件按照一定方法生成。事件牵涉的实体与方块会被系统记录下来；这些实体与方块被玩家以事件要求的方式操作之后，产生掉落物。掉落物中的金钱不作为实体掉落，而是通过Economy API直接入账并发送消息；其他掉落物直接在原地生成，由玩家自行拾取。

开放世界遭遇在Fabric API与原版代码上的落地点如下。周期检查使用ServerTickEvents或时间服务周期回调。玩家位置来自WorldGeo空间解析。声音、粒子和标题提示通过ServerPlayer连接发送。实体生成使用ServerLevel实体生成接口。临时方块变化必须记录原方块状态和过期时间，服务器停止或事件异常结束时执行清理。天气和区域效果优先使用WorldGeo timed effect overlay；只有确需改变世界天气时才调用原版天气接口，并记录恢复策略。

事件消息包括生成预警、进行提示和结算通知。事件详情菜单展示空间、参与玩家、收益状态和待结算状态。抽点种子、精确权重和反刷判定作为系统私有参数维护。

生成周期和强度与月相挂钩。满月时生成效率和强度达到最高。月相以月亮亮度作为代理变量，用乘数影响生成效率和事件强度。新月乘数修改为0.15。

| 月相 | 满月 | 亏凸月 | 下弦月 | 残月 | 新月 | 蛾眉月 | 上弦月 | 盈凸月 |
|------|------|--------|--------|------|------|--------|--------|--------|
| 月亮亮度 | 1 | 0.75 | 0.5 | 0.25 | 0 | 0.25 | 0.5 | 0.75 |

生成周期基准值为200个游戏刻。非满月时，生成周期长度除以相应月亮亮度。新月按0.15处理。

每个野区Region所拥有的GeoScope，面积每10000个方块给予一个事件额度，不满10000按10000计算。每个生成周期中，系统检查GeoScope内玩家数量和运行中事件数目。运行中事件数少于玩家数量两倍，且运行中事件数小于事件额度时，系统抽取事件种类并抽取点位生成事件。事件指定生成在玩家周围时，系统随机抽取GeoScope内一名符合事件生成要求的玩家作为目标。事件选中后检查生成要求。事件生成后，目标玩家离开GeoScope或下线时，只要事件涉及的区块仍被加载，事件继续，不取消；若事件区块被卸载，必须按照查阅文档确认的明确方式处理临时实体与临时方块状态，不得悬空。

事件点位抽取不得直接遍历超大区域的每个方块。应由WorldGeo提供形状内随机点或边界采样工具，Adventure在抽到(x,z)后使用原版高度图查询地表，再根据事件要求检查天空可见、流体、方块承载、实体碰撞和加载状态。未加载区块不强制加载，抽中未加载点位时本次生成失败并记录原因。

## 产出与掉落

野区奖励视为五类：拒绝掉落、高档物品、趣味物品、数字金钱和基础兑换物品。

- **拒绝掉落**：一次产出判定的不掉落结果。区域热度越高，拒绝掉落的常见度越高。
- **高档物品**：具有略高于原版属性的物品，指两种情况。一，工具、武器或装备的某项属性值X，根据该项属性在原版能获取之值Y，处于Y+1到Y+3之间的某个值。二，本来冲突的两种或多种属性，出现在同一个物品上。
- **趣味物品**：与属性超纲无关、使用时会获得效果的物品。这部分内容需要RPG物品mod基础之后制作。
- **数字金钱**：通过Economy API发放的金钱。完成事件要求的行为都有几率掉落金钱，额度从5元开始逐级翻2倍，直到640元为止；常见度从15开始逐级乘1/3，额度越大，常见度越低。个人或社区名义占领可占领GeoScope时，每主体每周在结算周期末获得500元基础占领金钱。
- **基础兑换物品**：四级兑换货币，即实物金币，全部使用原版物品加自定义名称与lore实现。

常见度是一个奖励项目在事件中被抽中的权重。抽取奖励时，以所有奖励项目常见度的总和为基底、本项目常见度为分子，确定本项目被抽中的概率。任何项目受到修正时，修正值同时应用到该项目在基底加总中的值和作为分子的值，即任何项目同一次掉落中在分子与分母中的值一致。

所有掉落通过配置驱动，事件模板声明可掉落的兑换货币条目和奖励条目，系统根据防刷参数计算实际权重。不同层次玩法在文档和代码结构上隔开，事件逻辑只引用模板编号和兑换货币ID，不直接拼装ItemStack。玩家可见掉落为具体物品和兑换货币，系统私有参数保留权重、随机种子、防刷修正和发行曲线细节。

### 防机械刷取与兑换货币发行机制

本机制属于系统私有的产出健康机制。玩家文档只说明野区会依据区域热度、活动多样性和奖励健康度调整长期产出体验；具体图层、权重、阈值和发行曲线保留在系统私有参数中。

Adventure建立防机械刷取图层，并参考GeoScope范围。图层颗粒度为4x4个区块。4x4区块内每发生一次有效奖励获取，且奖励内容并非拒绝掉落事件，就累积一次以玩家为名称的记录。记录在每周周末重置，纳入统一的周结束任务执行。

防机械刷取图层对所有掉落事件全局影响拒绝掉落常见度。对某个4x4区块元素而言，该范围内所有玩家记录值总和线性倍乘拒绝掉落类别的常见度。

兑换货币发行采用类比特币的累计通胀曲线。每种兑换货币按自然周维护服务器累计发行量，达到周期发行上限后基础掉落权重减半。同时，4x4区块累计产出和玩家近24小时（现实时间滑动窗口）获取量进一步降低实际掉落权重。三种因子叠加后，机器人或集中刷取的边际收益递减。

防机械刷取图层由Adventure持久化，WorldGeo只提供坐标归属和事件统计事实。图层键由维度、GeoScope编号、4x4区块坐标、自然周、玩家UUID和兑换货币ID组成。Adventure在奖励确认后写入图层，而不是在原版击杀或采集发生时写入，避免没有产生Adventure收益的普通行为污染防刷记录。

防机械刷取机制的玩家传达采用正向保密定义：系统会维护区域热度、活动多样性和奖励健康度，用于保持野区长期产出。热度状态通过boss条向玩家展示，玩家可以开关该boss条，且仅在野区内显示；其他野区状态信息也可以落地到该boss条。玩家可见提示只展示“该区域近期产出热度较高”“建议更换地点或玩法”等状态。OP可见调试页展示图层键、周期、计数、奖励记录、累计发行量和重置状态。具体权重、阈值、发行曲线和拒绝掉落调整保持为系统私有参数。

### 四级兑换货币

野区主产出为四级兑换货币，全部使用原版物品加自定义名称与lore实现，按价值和来源分层。兑换货币与Economy金钱（数字货币）分离：前者是实物物品，用于兑换奖励；后者是账户余额，用于地皮交易、建设收益和战争保证金等。

| 兑换货币 | 原版基底 | 主要来源 | 定位 |
|------|----------|----------|------|
| 竹币 | 竹子 | 开放世界遭遇、日常野区 | 最基础兑换货币 |
| 铜币 | 铜锭 | 遭遇事件、区域任务 | 低值兑换货币 |
| 金币 | 金锭 | 遗迹探索、解谜、高难事件 | 高值兑换货币 |
| 黑金币 | 下界合金锭 | 占领战争、稀有事件 | 顶级兑换货币 |

兑换货币为纯实物物品，不存在账户与余额；Adventure只维护发放流水。

事件模板直接声明兑换货币掉落条目。例如TNT硫方怪雨可配置为70%权重掉落竹币、30%权重掉落铜币。实际掉落权重再经过全局发行曲线、4x4区块热度、个人衰减三层修正。

### 金钱

金钱指通过Economy API管理的数字货币，与四级兑换货币（实物物品）分离。金钱不占用背包，直接存入玩家账户或社区国库。

完成事件要求的行为都有几率获得金钱奖励，例如打硫方怪。金钱额度从5元开始，额度逐级翻2倍，直到640元为止；常见度从15开始，逐级乘1/3，额度越大，常见度越低。个人或社区名义占领可占领GeoScope时，每主体每周在结算周期末获得500元基础占领金钱。

金钱不应以掉落实体作为最终账户事实。玩家在线或离线时均通过Economy UUID账户API直接入账。Adventure收益记录保存Economy交易编号和唯一外部引用。Economy保存异常时，Adventure保留已确定的收益记录并沿用原外部引用重试，现场展示说明收益待结算。

### 高档物品

高档物品是具有略高于原版属性的物品，指两种情况：

1. 工具、武器或装备的某项属性值X，根据该项属性在原版能获取之值Y，处于Y+1到Y+3之间的某个值。
2. 本来冲突的两种或多种属性，出现在同一个物品上。

示例：

| 名称 | 属性 | lore | 常见度 | 附加说明 |
|------|------|------|--------|----------|
| 复合弓 | 无限；经验修补 | 简单的复合材质工艺 | 1 | 无 |

高档物品生成封装在Adventure物品工厂中。工厂接收模板ID、随机种子、掉落来源和玩家显示信息，输出原版ItemStack。属性、附魔、lore和自定义标记通过当前Minecraft版本可用的数据组件或NBT兼容层写入。事件逻辑只引用模板编号，不直接拼装ItemStack。

### 趣味物品

趣味物品与属性超纲无关，使用时会获得效果。这部分内容需要RPG物品mod基础之后制作，当前阶段不落地。

### 资源交易与发放抽象

金钱、兑换货币与奖励物品遵循各自的资源边界。本节是资源处理的正文规范。

- **金钱（数字货币）**：通过Economy UUID账户API直接入账或扣款。玩家在线状态不参与交易判断。余额不足时明确失败，Economy保存异常时沿用原外部引用重试。
- **兑换货币与奖励物品（实物）**：事件结算时在现场原地生成ItemStack，由玩家自行拾取，不按玩家UUID补发，也不建立离线待领取队列。消费与兑换仅扣除在线玩家背包中的物品，并严格匹配名称、lore、附魔和NBT。
- **余额/资源不足**：立即失败，不透支；结算执行阶段失败则进入待处理状态重试，不减少金额。
- **社区层面**：金钱统一调用Community国库API。两阶段结算，失败不重算。

### 收益记录

收益历史菜单展示个人、庄园和领域的收益记录。记录项包含时间、空间、事件来源、参与主体、实物生成状态、金钱状态、Economy流水编号摘要和Community入账摘要。可点击结算消息打开对应收益记录。待结算记录展示失败阶段、下次重试时间和已确定事实。随机细节绑定在已确定记录中作为系统私有参数维护。

## 战争设计

战争发生在被Adventure配置为可占领的野区GeoScope。可占领区域分为小型野区和城邦级产地。任何个人、庄园或领域主体都可以宣战：个人主体可以争夺小型野区，庄园和领域可以争夺两类区域。战争窗口开始前，系统公布区域名称、范围、据点、保证金、最低参与条件、当前占领者、历史占领周期和预计周收益。

宣战需要支付保证金100元（Economy数字货币），宣战后直接参战。轻惩罚规则下，保证金承担防骚扰成本。进攻方在战争窗口内达到最低参与条件（战争分75分）后，保证金退回80%。进攻方参与不足时，保证金退回50%，其余50%划入防守方国库，无防守方时由系统回收。死亡按原版或服务器既有规则处理，战争机制扣除现场未结算活动收益，不扣玩家已有账户余额。

占领判定采用两个可落地计分点：连续占点和敌对击杀。战争分按贡献口径累计：每次`hold_10m`占点流水计1分，每次`kill`击杀流水计10分，主体战争分为其效忠成员分数之和。每个可占领GeoScope配置1到3个战争据点，据点必须由SubSpace承载，提前由管理员配置，并标记所属单位领地。战争窗口内，已报名玩家选择效忠主体后进入指定据点SubSpace；玩家连续10分钟存活且未离开该SubSpace时，Adventure为其效忠主体写入一次`hold_10m`占点流水。玩家短暂离开SubSpace时，系统每秒发送消息提示，5秒内返回则计时继续；离开超过5秒、死亡、下线或切换效忠主体都会清空本次连续计时。击杀敌对效忠主体玩家时，Adventure写入一次`kill`击杀流水。对单个玩家，若其本自然周内在该野区Region内的击杀死亡比小于0.5，则其在该Region内的击杀得分无效。窗口结束时，战争分最高且达到最低门槛75分的主体取得占领权。全部主体低于门槛时，占领状态保持原主，但原主状态最多连续维持两周；之后若仍然全部主体低于门槛，区域转为空置。

占领权按周运行。每个区域每周开放有限战争窗口，窗口以服务器自然周为基准配置，占领权在一周末尾切换。占领者在本周末取得固定金钱收益和区域提示展示。区域收益不直接替代普通冒险掉落，而是提高组织通过成员活动把野区产出转化为国库资产的能力。

战争据点由WorldGeo SubSpace承载。Adventure保存据点配置、单位领地归属、计分规则和分数流水，WorldGeo只负责SubSpace范围、进入离开、PVP/传送等通用设置。连续占点由WorldGeo进入离开事件、玩家在线状态、死亡事件和Adventure周期检查共同计算。击杀事实优先来自WorldGeo通用行为事件。战争区域以特别标明的空间属性表达：战争区域内不参战主体没有PVP权限；社区参战后，其全部成员获得战争区域PVP权限；成员加入或退出参战社区时，同步处理其在参战区域内的PVP权限。

战争窗口由时间服务驱动。窗口状态、保证金、最低参与门槛、效忠对象、连续占点计时、战争分流水和占领结果都保存在Adventure。Community只提供组织身份、国库扣款、国库入账和成员广播。WorldGeo不保存占领者，也不解释战争胜负。

战争菜单落地为战争区域列表、窗口详情、报名/效忠选择、保证金确认、占领得分页、占领结果和历史记录。区域列表展示区域名称、范围、当前占领者、下一窗口、保证金和预计公共收益。窗口详情展示规则、最低参与条件、传送限制、据点摘要和当前公共战况。报名确认页展示效忠主体、保证金来源、退款条件、参与不足后果和窗口时间。占领得分页向玩家展示各效忠主体总分、各据点当前控制状态、本人当前连续占点计时、本人已贡献的`hold_10m`次数和`kill`次数；向组织管理者增加成员贡献排行、保证金状态和预计占领结果；向OP增加每条计分流水、离线/死亡清零记录和手动重算入口。

战争消息包括窗口预告、窗口开启、报名成功、保证金扣款、连续占点完成、击杀计分、参与不足、战况阶段、窗口结束、占领结果和周收益结算。公共消息展示可核查事实、当前领先主体、各据点控制状态和分差区间；组织管理者消息增加国库扣款、入账、成员贡献摘要和占领得分页入口；系统私有参数保留异常参与判定和风控细节。

## Adventure落地方式

Adventure负责把通用空间、社区组织和Minecraft原版事件解释为冒险规则。野区是Adventure对Region或GeoScope配置的解释。战争据点、交付点、活动场地和小游戏边界是Adventure对SubSpace配置的解释。个人、庄园和领域是Adventure结算时使用的参与主体。庄园和领域的成员、权限、账户和公告由Community提供接口；空间归属、进入离开、玩家枚举、几何查询和空间统计由ImyvmWorldGeo提供接口。

Minecraft原版提供实体、方块、战斗、死亡、物品、容器、天气、月相、维度和时间。Adventure监听击杀、死亡、实体伤害、物品使用、容器开启、方块变化、玩家移动和周期tick。监听结果先转化为冒险事件，再进入事件生成、贡献计算、掉落计算、分红结算和防机械刷取计算。

Adventure需要持久化区域配置、效忠对象选择、战争窗口、占领权、保证金、贡献明细、收益流水、防机械刷取计数、奖励物品模板和兑换货币发放流水。区域配置以Region、GeoScope和SubSpace编号作为外键。玩家、庄园和领域以对应系统提供的稳定主体编号作为外键。防机械刷取图层以4x4区块为单位，每周重置，记录玩家、参与主体、GeoScope和掉落类别。

Adventure代码结构应分为infra、application、domain和entrypoint。infra只处理Fabric API、mixin、原版ItemStack/Entity/World交互和下层API适配。domain保存事件生成、掉落、贡献和战争公式，并输出面向菜单和消息的只读视图模型。application编排一次事件、一次结算、一次战争窗口、一次菜单动作或一次消息通知。entrypoint注册命令、菜单、数据加载和事件监听。domain不得直接调用Minecraft原版对象，也不得直接调用Community或WorldGeo数据库。

### TNT硫方怪雨

硫方怪雨是开放世界遭遇事件的基础实例。硫方怪（Sulfur Cube）是新版本生物，被动类史莱姆，可吸收完整方块（包括TNT），8点血量，免疫摔落伤害，击杀后分裂为小个体；本事件中的硫方怪为含有TNT的个体。事件目标是利用坠落硫方怪制造异变反应，并从爆炸后的现场取得异变产物。玩家的主要操作包括撤离、引怪、控场和产物收集。

故事背景按如下方向书写。

> 异变区域的硫元素生物在爆炸中撕开短暂反应层。怪物和中立生物被卷入反应层时，会留下可被猎人收集的异变产物。

事件生成前先有持续5秒到10秒的预警。目标玩家周围出现硫化粒子、低沉音效和短文本提示，标明事件方向、预计坠落强度和撤离建议。

事件强度等于满月基准强度乘月亮亮度，再加正负1以内的正态分布波动，结果向上取整。满月基准强度为5个。系统以目标玩家为中心，在包括玩家所在位置的9x9坐标范围抽取不重复点位，点位数量等于强度值。系统找到这些点位的最高方块位置，然后在这些方块以上平均10格、随机正负3格的高度生成硫方怪。硫方怪落地后被引燃，引燃时间以5秒为基准，按正态分布在正负2秒内取值。

这些硫方怪被玩家操作或触碰要产生记录。只有产生记录才会掉落奖励。每只硫方怪爆炸产生的奖励归属于记录的最后一个玩家：其中的金钱通过Economy API入账，其他掉落物原地生成，由该玩家拾取。爆炸直接杀死怪物和中立生物时，系统生成主要收益掉落。爆炸炸死被动生物时也产生掉落，但是拒绝掉落常见度乘10。怪物与中立生物的高档掉落概率根据评定怪物强度增加。评定怪物强度每增加1，对应高档掉落概率增加10%。评定怪物强度为13.5时，高档掉落概率增加135%。

## 附录：指标运算方法

高档物品视为高档掉落物。

评定怪物强度由血量和攻击力计算。怪物每5点血量增加1点强度。一般僵尸血量为20，因此增加4点强度。攻击力采用该怪物在困难模式下最强一次性攻击方式的理论伤害。特殊伤害可以一击必杀时，视为一次性打出20点伤害。TNT作为实体参与评定怪物强度时，血量视为5，攻击力以TNT最大伤害为准。
