# 跨项目技术原则

文档性质：技术原则正文。适用范围：ImyvmEconomy、ImyvmWorldGeo、WorldGeo-CommunityAddon、WorldGeo-AdventureAddon及关联项目。本文内容应写入各项目专有的AGENTS.md，作为实现约束长期生效。

## 1. 资源交易统一抽象

- 金钱（数字货币，Economy API管理）与兑换货币、物品（实物）严格区分。
- 金钱按UUID账户API入账或扣款，返回结构化结果与交易编号，金额单位为分。
- Adventure兑换货币与奖励物品在事件现场原地生成。实物消费与兑换仅从在线玩家背包扣除。
- 金钱操作必须原子，余额不足明确失败，不透支、不拆分、不借债。
- 实物扣除严格匹配物品 ID、自定义名称、lore、附魔和 NBT，避免误扣普通原版物品。

## 2. 两阶段结算

- 确定阶段保存主体、数量、来源和周期，生成不可变结算记录；执行阶段负责实际转移。
- 执行阶段失败时不重新计算或随机；结算记录保持待处理状态，重试沿用已确定事实。

## 3. 在线与离线边界

- 金钱：Economy按玩家UUID直接入账或扣款，在线状态不参与交易判断。保存异常由来源模块保留结算记录并沿用原外部引用重试。
- Adventure兑换货币与奖励物品在事件现场原地生成，由玩家自行拾取，不建立按玩家UUID保存的离线待领取队列。
- 实物消费与兑换仅扣除在线玩家背包。玩家离线时直接拒绝，不生成待扣记录。

## 4. 失败重试契约

- 待处理记录字段：cycle id、主体、资源、金额或数量、来源、外部引用、失败阶段、失败原因、重试次数、下次重试时间。
- 重试时机：下一结算周期自动重试或OP手动触发；重试沿用已确定事实、随机结果和外部引用。
- 待处理队列必须持久化，服务器重启后恢复；不得因重试重复结算同一 cycle id。
- 失败原因按余额不足、API异常和业务输入非法等类别保存，便于重试或人工处理。数字金钱没有玩家离线失败状态。

## 5. 周期与流水

- 所有结算记录携带 cycle id 与 transactionId（Economy 或 Community 流水编号），用于对账与幂等。
- Economy流水支持按账户与时间分页查询、指定条目详情和受控回退。外部来源流水由来源模块协调业务记录与账户余额回退。
- 周期边界以 WorldGeo 时间服务为准，默认东八区；服务器启动时补算错过的周期，但不重复结算同一周期。
- 周结束行为（防刷热度重置、占领结算、税收福利结算等）纳入统一的周结束任务管理。

## 6. 权限转移

- 地皮等涉及权限转移的交易先保存价格、双方和地皮编号，随后执行扣款与入账，最终执行WorldGeo权限写入。
- 权限写入失败时回滚资金或保持待处理状态，不允许出现"钱已付、权未转"且无记录可查的状态。
- 交易后原所有者的地皮权限被清除；若原所有者属于该地皮所属社区的管理人员，其权限保留；建筑保持不动。

## 7. 信息分层

- 所有玩家交互分为玩家可见、管理者可见、OP 可见、系统私有四层；该分层只影响信息发送。
- 系统私有参数（随机种子、精确公式、风控阈值、反刷权重）只存于服务端持久化与配置，不加密，但绝不出现在任何下行消息、菜单 lore 和提示中。

## 8. 分层与依赖

- 下层项目不出现上层语义；上层只通过下层公开 API 组合能力，不直接依赖下层 infra、application 或 mixin 包。
- 与 Minecraft 原版代码的交互集中在各项目的 infra 或 entrypoint 层；Fabric API 优先于 mixin。
