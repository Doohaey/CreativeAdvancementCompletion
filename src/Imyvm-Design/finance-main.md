# 金融模拟交易系统设计理念与落地大纲

## 系统定位

金融模拟交易系统由独立Fabric服务端mod承载，暂定项目名为`ImyvmFinance`。系统使用`ImyvmEconomy`的游戏币，围绕公开指数行情发行服务器内部的指数模拟份额。玩家交易行为发生在服务器经济内部，现实市场行情提供价格参照，服务器根据行情快照、手续费、滑点和持仓规则完成买入、卖出、冻结、退款与异常结算。

指数模拟份额的设计对象是游戏内风险资产。玩家通过上证指数、沪深300、恒生指数、标普500、纳斯达克100、日经225和韩国综合股价指数等标的感知现实市场变化。行情刷新保持低频，交易依赖服务器已确认快照。该节奏保留新闻判断与跨时区市场节律带来的乐趣，也把免费行情接口的运行代价限制在服务器可承受范围内。

系统成交以系统做市为基础。玩家向系统买入指数份额，也向系统卖出指数份额。玩家间订单簿、限价单和撮合成交属于后续扩展方向。系统做市减少了交易对手不足造成的玩法中断，使第一阶段能够集中验证行情接入、持仓计算、资金冻结、异常恢复和审计流水。

## 现实机制参照

现实证券市场以委托、申报和撮合为中心。上海证券交易所和深圳证券交易所的竞价交易采用集合竞价和连续竞价，连续竞价依照价格优先、时间优先原则撮合。中国大陆A股交易还存在佣金、经手费、证管费、过户费和卖出侧印花税等费用结构。服务器金融系统吸收其中的成本、成交确认和交易时段概念，但指数模拟份额本身由服务器发行和回收，成交对手方由系统做市承担。

现实指数通常通过ETF、基金或期货产品间接交易。服务器机制采用指数点位作为游戏内份额价格，不复制真实证券账户、清算机构和交易所会员体系。该处理降低了规则解释成本，也让游戏币资产与行情波动之间形成直接关系。

## 运行依赖

`ImyvmFinance`在`fabric.mod.json`中声明对`imyvm_economy`的依赖。金融系统通过`DatabaseApi.getInstance().getPlayer(player)`取得`PlayerWallet`，并使用`getMoney()`、`takeMoney(amount)`和`addMoney(amount)`完成余额查询、扣款和退款。资金冻结通过扣除玩家钱包余额实现，订单取消、过期、成交差额和异常恢复通过加款返还。

金额沿用`ImyvmEconomy`的`Long`底层单位。玩家可见金额遵守经济系统现有展示规则。指数价格使用定点整数保存，建议以指数点位乘以`10000`作为价格单位。份额同样使用整数保存，`1`个份额单位代表`0.1`份，`10`个份额单位代表`1.0`份。结算公式在整数域内执行，比例项以基点或万分位保存。

## 行情数据

行情接入由本地sidecar服务承担。sidecar使用Python和AKShare作为默认实现，负责访问免费行情来源、归一化字段、生成快照编号、写入本地缓存和暴露HTTP接口。Fabric mod访问`localhost`上的稳定JSON接口，随后把行情快照写入SQLite。Minecraft服务器主线程只读取本地缓存结果，外部请求运行在sidecar和异步刷新任务中。

sidecar返回的数据包含快照编号、数据源、抓取时间、市场时间、指数代码、指数名称、价格、涨跌幅和市场状态。Fabric mod不依赖东方财富、新浪财经或交易所页面的原始字段。数据源变化停留在sidecar内部，mod领域层面对`QuoteSnapshot`和`MarketQuote`两个稳定对象编程。

行情刷新按市场状态分层。开市市场每5至15分钟刷新一次。休市市场每15分钟至1小时刷新一次，用于维护开盘市价单的等待状态和最近有效快照。快照超过配置的最大年龄后，该标的进入受限状态，系统接受查询和撤单，并把新成交交给开盘快照或管理员结算流程处理。

## 份额交易

每次买入生成一笔独立仓位。仓位记录保存玩家UUID、指数代码、买入份额、剩余份额、冻结份额、买入快照、买入价格、手续费、滑点、买入时间、最早卖出时间和状态。多次买入同一指数保持为多笔仓位。该结构让冷却、跨快照判断和部分卖出具有可审计依据。

买入金额由指数点位、份额、买入滑点和买入手续费共同决定。

```text
买入成交价 = 指数点位 * (1 + 买入滑点)
买入总成本 = 买入成交价 * 份额 * (1 + 买入手续费)
```

卖出金额由指数点位、份额、卖出滑点和卖出手续费共同决定。

```text
卖出成交价 = 指数点位 * (1 - 卖出滑点)
卖出到账 = 卖出成交价 * 份额 * (1 - 卖出手续费)
```

卖出命令使用`positionId`指定仓位。玩家可以卖出该仓位的部分份额，最小单位为`0.1`份。卖出后仓位的`remainingUnits`减少，交易流水保存卖出价格、手续费、滑点、到账金额和实现盈亏。

## 市场时间

开市中下单按最新成功快照成交。非开市下单生成开盘市价单。开盘市价单等待对应市场下一次开市后的第一个成功行情快照，并以该快照价格执行成交。玩家可以在开盘前撤销pending订单。pending订单在72小时后自动过期。

买入开盘市价单按最近有效价格和安全垫冻结资金。

```text
冻结金额 = 最近有效价格 * 份额 * (1 + 安全垫)
默认安全垫 = 5%
```

成交成本低于冻结金额时，系统成交并返还差额。成交成本高于冻结金额时，订单取消并返还冻结金额。卖出开盘市价单冻结对应仓位份额，成交后按开盘快照价入账，撤单和过期则释放冻结份额。

开盘市价单把消息判断转化为提前排队行为。玩家在周末、夜间或海外市场开盘前能够表达交易意图，成交价格来自市场开盘后的新快照。该设计使新闻判断存在收益空间，过期收盘价无法直接成为成交价格。

## 延迟套利约束

卖出需要满足固定冷却时间和跨成功快照条件。固定冷却时间建议为30分钟。跨成功快照指仓位买入后，该指数至少出现过一个新的成功快照。两个条件共同决定`earliestSellTime`和可卖状态。

行情接口失败时，快照不推进，相关仓位的跨快照条件也不推进。快照年龄超过配置阈值后，系统暂停该标的的即时成交，pending订单继续等待有效快照，管理员可以通过异常结算模式处理长期受影响资产。

## 费用与风控

交易成本采用游戏平衡模型。默认买入手续费为`0.2%`，卖出手续费为`0.2%`。基础买入滑点为`+0.1%`，基础卖出滑点为`-0.1%`。大额交易按照单笔估算价值增加滑点。

| 单笔估算价值 | 额外滑点 |
| --- | --- |
| `10000`游戏币及以上 | `0.1%` |
| `50000`游戏币及以上 | `0.3%` |
| `100000`游戏币及以上 | `0.6%` |

玩家维度的风险约束包括每日买入额度、每日卖出额度和总持仓市值上限。默认每日买入额度为`100000`游戏币，每日卖出额度为`100000`游戏币，总持仓市值上限为`300000`游戏币。开盘市价单创建时预占每日额度和持仓额度，成交后按实际金额修正，撤单、过期和失败取消时释放预占额度。

全服总敞口限制作为配置项保留，默认关闭。服务器经济观察到指数交易注入或回收游戏币过多时，管理员可以启用全服总市值限制或单指数份额限制。

## 异常结算

异常结算模式处理行情源长期失败、快照字段异常、市场状态冲突、资金事务状态待判定和订单恢复歧义。系统把受影响标的、订单或仓位写入异常队列，并向管理员展示价格来源、最近成功快照、失败次数、冻结资金、冻结份额和待处理玩家数量。

管理员结算提供三类价格来源。最近成功快照适用于短时接口故障。管理员确认的收盘价适用于数据源恢复后补录。手动结算价适用于公开行情源缺失但管理员可以从可信来源确认价格的场景。每次处理生成结算批次，保存操作人、时间、价格、来源、范围、资金变化和份额变化。

普通玩家查看与自身订单、仓位和资金相关的处理结果。管理员查看完整异常队列和处理记录。系统私有的重试细节、数据源内部字段和恢复推断留在服务端日志与SQLite审计表。

## 数据持久化

金融系统使用SQLite保存行情、订单、仓位、交易、额度和审计。SQLite适合索引查询、崩溃恢复和幂等约束。业务事实先写入SQLite，再调用`ImyvmEconomy`公开API，随后写入资金操作结果。服务器重启后，系统按SQLite状态恢复pending订单、冻结资金、冻结份额、未完成交易和异常队列。

核心表包括`market_snapshots`、`market_quotes`、`positions`、`orders`、`trades`、`daily_limits`和`admin_settlements`。`market_snapshots`保存快照编号、来源、抓取时间、市场时间和状态。`market_quotes`保存快照内每个指数的价格、涨跌幅、货币和市场状态。`positions`保存每笔买入仓位的剩余份额与冻结份额。`orders`保存开盘市价单、冻结金额、冻结份额、预占额度、创建时间、过期时间和目标开盘市场。`trades`保存实际成交。`daily_limits`保存已用额度与预占额度。`admin_settlements`保存人工处理批次。

幂等约束以订单ID、交易ID、快照ID和结算批次ID为中心。相同订单在相同快照下产生一次成交。相同结算批次执行一次资金变化。资金调用状态不明时，系统读取本地尝试记录和玩家当前余额进行核对；无法自动证明的事务转入管理员处理。

## 命令交互

第一阶段以命令为主。命令补全提供指数代码、指数名称、仓位短编号和订单短编号。玩家输入可以使用代码，也可以使用可读名称候选。

```text
/market list
/market quote <symbol>
/market buy <symbol> <units>
/market sell <positionId> <units>
/market positions
/market orders
/market cancel <orderId>
/market history
/market ranking daily
/market ranking weekly
/market ranking total
/market status
/market admin reload
/market admin settlement ...
```

`/market positions`展示指数、剩余份额、冻结份额、买入价、当前估值、浮动盈亏、最早可卖时间和引用快照。`/market orders`展示pending订单、冻结金额或冻结份额、过期时间、目标市场开盘时间和撤单入口。`/market history`展示成交时间、价格、手续费、滑点、净额和实现盈亏。

玩家消息写清指数、份额、金额、价格来源、行情时间、手续费、滑点、冻结状态和下一次可操作时间。非开市下单消息写明订单将在开盘后的首个成功快照成交，使玩家清楚当前余额扣除属于冻结资金。

## 收益展示

系统展示实现盈亏、浮动盈亏和收益率排行。实现盈亏来自已卖出交易。浮动盈亏使用最新有效快照估算。总收益等于实现盈亏加浮动盈亏。收益率等于总收益除以已投入本金。

排行榜分为日榜、周榜和总榜。日榜最低投入本金为`10000`游戏币，周榜最低投入本金为`30000`游戏币，总榜最低投入本金为`50000`游戏币。排行榜展示统计周期、快照时间和收益率，不发放游戏币奖励。荣誉展示提供竞争感，经济增发保持由交易盈亏本身决定。

## 信息分层

普通玩家查看自己的余额影响、冻结资金、冻结份额、持仓、订单、成交历史、收益和排行榜摘要。管理员查看行情源状态、快照时间、失败次数、pending订单总量、异常队列和手动结算入口。系统私有信息包括失败重试细节、数据源内部字段、恢复推断和反刷判定。

聊天消息、命令反馈和后续菜单需要使用同一套信息分层。玩家可见层展示当前事实、操作成本、成交结果和下一次可操作时间。管理员可见层增加系统状态、异常处理和审计入口。服务端日志保存完整技术细节。

## 后续扩展

玩家间订单簿适合在系统做市运行稳定后加入。该扩展需要资金与份额冻结、价格优先与时间优先排序、部分成交、撤单、撮合流水和重启恢复。限价单依赖同一套订单簿能力。杠杆、做空、期货、ETF和个股交易涉及更高波动与更复杂数据源，适合在指数份额机制完成压力测试后单独设计。

## 资料入口

深圳证券交易所《交易规则》提供竞价交易、交易时间、价格优先和时间优先等规则文本。上海证券交易所投资者服务页面列出交易时间和主要费用项目。财政部、税务总局2023年第39号公告规定自2023年8月28日起证券交易印花税减半征收。AKShare文档提供股票指数、港股指数、美股指数和全球指数等公开数据接口说明。上述资料用于确定现实参照和免费行情接入方向，服务器内成交、费用和风控参数按游戏经济平衡设置。
