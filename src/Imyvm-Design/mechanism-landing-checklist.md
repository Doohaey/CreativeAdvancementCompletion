# 机制落地最小清单

任何新机制从设计进入实现前，至少要补齐以下方面。

1. **需求来源模块**：说明机制由哪个设计模块提出，例如 Community、Adventure、区域升级工具或全局经济。
2. **落地承载模块**：说明最终由哪个仓库实现，不能把上层语义下沉到底层。
3. **玩家可感知行为**：说明玩家看到、点击、输入、领取、亏损或结算的具体体验。
4. **下层 API 契约**：列出需要读取和写入的 WorldGeo、Community、Economy、Hoki API；缺失 API 要单独设计。
5. **数据与持久化**：列出需要保存的对象、稳定外键、周期编号、流水编号、失败重试状态和旧数据兼容策略。
6. **原版/Fabric 交互**：说明监听、拦截、实体/物品/世界修改位于哪个 infra 或 entrypoint 模块。
7. **菜单与命令**：说明玩家、管理者、OP 分别在哪些界面操作，展示哪些必要信息，隐藏哪些不可公开细节。
8. **结算流程**：说明何时冻结事实、何时计算、何时入账、失败如何回滚或重试，如何避免重复结算。
9. **风控与反刷**：说明资金上限、材料约束、冷却、关联主体、异常转移、热度衰减和不可公开判定。
10. **兜底与熔断**：说明亏损救济、触发后限制、通知口径、通胀控制和保密内容。
11. **测试要求**：覆盖正常路径、边界阈值、重启恢复、重复提交、余额不足、API 失败、旧数据加载和关联主体绕过。
